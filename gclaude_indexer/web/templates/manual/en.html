1. What it is and what it is for

GClaude Indexer reads a folder full of documents (PDFs, Word files, spreadsheets, e-mails, scanned images) and builds, on your computer, an index of everything in it: what each item is, its date, who it is from, which page it is on. This index is made to be used with Claude.

It solves five problems:

  1. Saves your Claude subscription. Instead of sending the whole collection for Claude to read, you hand over just the index. Claude looks at the index, finds which document and which page matter, and opens only that.
  2. Collections far larger than Claude can handle. Claude has a limit on how much text it considers at once. A compact index, split by group, fits within that limit even when the collection has thousands of pages.
  3. Confidentiality. Reading, text recognition (OCR) and classification happen on this machine. No document is sent to the internet during processing. The database lives in a folder of yours. If that folder is on Google Drive, you can use it from any computer.
  4. Updates without starting over. When you add, change or remove documents, the program redoes only what changed.
  5. Personal or team use. It works for a single person or for a team sharing the same folder on Drive or on a file server.

2. Quick start in 6 steps

  1. New project. Click + New project, give it a name, choose the Source folder (where your documents are) and check the suggested Output folder. Everything else can stay as it is. Click Create project.
  2. Run everything. On the Execution screen, click Run everything up to classification. You can leave the window open and do something else: the progress updates on its own.
  3. Generate the reports. When classification finishes, click Import and generate reports.
  4. Check. The Result screen shows the quality, the pending items and a preview of each generated file.
  5. Download the package. Under Package for a new Claude Project, click Download package (.zip).
  6. Take it to Claude. On claude.ai, create a Project, paste the contents of project_instructions.md into its instructions and upload the other files as project knowledge. See the details in Using it with Claude.

Tip: on every screen, the Help button at the top opens a summary of that screen, and the ? icon next to each field explains the field.

3. Try it with the demo collection

You do not need a collection of your own to see what the program produces. The demo/acervo folder in the GitHub repository is a small, entirely made-up collection: 72 pages and 41 items, with two volumes of a case file in PDF, a contract, a memo in Word, a spreadsheet, a scanned official letter and an e-mail. The file demo/gabarito.csv says what each page is. The installer does not include this folder: download the repository as a ZIP (the Code button, then Download ZIP) or clone it.

  1. Create a project with the source folder pointing to demo/acervo. Check PDF, Word, Excel, images and e-mail under the extensions.
  2. Run everything up to classification. With the rules engine it takes seconds; with the local model, a few minutes.
  3. Generate the reports and open index.md in the output folder. Compare it with gabarito.csv, or measure the accuracy with the tool described in What accuracy to expect.

4. Projects screen

Lists every project this computer knows about. Each project lives entirely in its output folder (the project.db file inside it holds everything).

  • Status: not started (nothing read yet), in progress (some step is running), classification pending (there are still passages to classify) or the number of items already done.
  • Open: takes you to the project's Execution screen.
  • Delete: takes the project off the list. You choose between Only remove from the list (the files stay on disk) or also delete the generated files. In that case the program deletes only what it created itself (database, reports, buscar.bat, the local work folder). Your own files that are in the output folder are kept, and the folder only disappears if it ends up empty. The source folder is never touched.
  • Open existing project: for a project that is not on the list (reinstallation, new computer, folder received from someone else). Just point to the output folder.
  • Shared catalog: see Another computer and team use.
  • Sets: several collections in a single Project. See Sets.

5. New project: every field

In most cases you only need to fill in Name and Source folder. The other fields already come with values that work well.

Identification

Project name
Just so you can recognize the project on the list. It does not change any file.
Collection theme
One or two sentences about the content (e.g. "bidding process for construction project X"). It goes into the instructions generated for Claude, and it is what helps the local model most in understanding what it is reading.

Folders

Source folder
Where the original documents are. It is never changed: the program only reads it.
Output folder
Where the reports and the database are saved. The default is the source folder with _indexado added at the end. It can be on Google Drive or on a file server so it can be used from other computers. The intermediate files (PDFs with OCR, text slices) go to a local work folder on this machine, not here, so that gigabytes are not synced.

Collection

Collection type
case file numbers by sheet (f. 1, f. 2...), like an administrative or court case file; the numbering carries on from one volume to the next. library numbers by page (p. 1, p. 2...), like books and reports.
How to group
A "group" is a set of files that form a unit (a case file with several volumes, for example). by subfolder uses the name of the first subfolder, the most common case; by name pattern groups by the beginning of the file name, using the next field; all together treats the whole folder as a single group.
Grouping pattern
Only for by name pattern. It is a regular expression, an advanced option: if you do not know what that is, leave it blank. Example: ^(\d{4}-\d+) puts 2024-001 - petição.pdf and 2024-001 - despacho.pdf into the group "2024-001".
Included extensions
Which file types are included. Check ALL to accept any text or document format (executables, compressed archives and .ini files are never included). Web pages (.htm, .html, .mht) are read as clean text, without the markup, and the encoding of every text file is worked out automatically (UTF-8, Windows-1252, ISO-8859-1), with nothing to configure. Text struck through in the original, in HTML, DOCX, PPTX or XLSX, appears as ~~text~~: in legislation, that is a revoked provision.

Slicing, windows and OCR

A window is a run of consecutive pages that the classifier reads at once to figure out where each item starts and ends.

Automatic proposal. When you choose the source folder, the program surveys a sample of it (up to 6 seconds): how many PDFs, scanned or not, how many whole documents (HTML, DOCX, TXT), page sizes and language. From that it proposes the five values below, each with its reason. Click Apply these settings to use them; nothing changes otherwise. The Analyse the folder and propose button runs the analysis again after you change the extensions.

Pages per block (80)
PDFs larger than this are cut into parts before processing, so huge files do not get stuck. It does not change the index.
Pages per window (16)
Smaller windows make fewer mistakes when many short documents are mixed together, but take longer. Larger windows are faster, but may merge two items into one.
Overlap (2)
How many pages from the end of one window are repeated at the start of the next, so an item is not cut in half. It must be smaller than Pages per window.
Characters per page (2000)
The limit of text from each page sent to the classifier. It keeps a page with a gigantic table from taking up the whole window. The collection search sees the whole text, without this limit.
OCR language
The language used to recognize the text of scanned pages: por (Portuguese), eng (English) or por+eng for both in the same collection. OCR only runs on pages that have no text; a PDF with text and a few scanned sheets in the middle gets OCR only on those sheets.

Classification

Classification engine
What identifies the items. See the comparison in Classification engines.
Local model
Which Ollama model the local engine uses. automatic chooses by the graphics card: qwen3.5:9b on a card with 8 GB of memory or more, qwen3.5:4b on smaller ones. Choosing another one is useful for comparing quality.
Processing
Whether the local engine uses the graphics card (GPU). automatic and force GPU use as much of it as possible, much faster. CPU/RAM only leaves the card free for other programs, but is slower.
Parallelism
How many files conversion and reading process at the same time. economical: one at a time; automatic: uses the processor cores and leaves one free so you can keep using the computer (recommended); maximum: finishes sooner, but the computer gets slow in the meantime.
Review low confidence
First runs the rules engine (instant) on everything and sends to the chosen engine only the passages where the rules were unsure. Saves time when the collection has many standardized documents.

Project instructions

Instructions you already use
If your Claude Project already has instructions, paste them here. They stay at the top of the generated instructions file and are never deleted. See Your instructions are preserved.
Role in the instructions
Replaces the default paragraph that tells Claude what its role is in this collection (e.g. "you are a legal assistant..."). If left blank, the default text is used.
Extra rules
Rules specific to the collection, added at the end of the instructions (e.g. "always cite the case number", a glossary of acronyms).

7. What accuracy to expect

The quality score on the Result screen says how much confidence the engine itself declared and how many fields it filled in. It does not say whether the item is right. For that, the index is measured against a hand-checked answer key on the demo collection, in every version that touches the classifier. In the latest measurement (02/11/2026):

  • No page was lost, with either engine. The program guarantees this: every page of the collection lands in some item of the index.
  • Rules: found 36 of the 41 items, got the type right for 94% of them, the date for half and the author for one in five. In 4 seconds.
  • Local model (qwen3.5:9b): got the date right for 89% and the author for 84% of the items found, but sliced items (65 in the index for 41 in the answer key). In 4 minutes.

In practice: the index takes Claude to the right page, and Claude checks the text in the original document before answering, as the generated instructions tell it to. Whoever programs can measure accuracy on their own machine with the tools/medir_acerto.py tool, over the demo collection's output folder. The full numbers, what each one means and what they do not say are in docs/QUALITY.md in the repository.

8. Execution screen: the steps

Processing always follows this order. Each step can be interrupted and resumed: pausing, closing the program or even turning off the computer midway does not break anything. When you run it again, it picks up where it left off.

  • 1. Scan: finds the files in the source folder and identifies duplicate copies (a document identical to another is included only once). A counter shows how many files have been seen so far; on a second scan, unchanged files are not read again.
  • 2 and 3. Conversion, OCR and slicing: turns each file into text. Scanned pages go through text recognition (OCR); huge PDFs are cut into blocks. This is the slowest step for scanned collections. A file whose OCR failed is redone the next time, and the step stays "pending" while there is one.
  • 4. Per-page extraction: stores the text of each page with its numbering (f. N or p. N) and builds the search index. The step only finishes when the search is ready.
  • 5. Window preparation: splits the pages into passages for classification.
  • 6. Classification: the chosen engine identifies each item: type, date, author, summary and page range.
  • Run next step: runs only the next step. Useful for following along step by step.
  • Run everything up to classification: chains all of them. This is what you will use almost every time.
  • Import and generate reports: after classification, puts the items together and writes the files for Claude. It is not part of "Run everything"; the program tells you when the time comes.
  • Activity bar: every long operation shows up in a bar with its name and a timer, which stays there if you reload the page (F5). If you ask for another operation on the same project while one is running, an "in progress" page appears; nothing is lost, just wait.
  • Live log: tells you what is happening, in plain language. The filter shows only warnings or only errors; copy copies the log so you can send it to someone. With the local model, the log says which graphics card is in use, whether the model fit in it and when the model's answer came back incomplete and was requested again.
  • Claude Code engine: a box appears with the phrase to say to Claude Code (process the windows). Open Claude Code in the output folder, say the phrase and, when it finishes, click Recheck if the windows are done.

9. Pausing and resuming

The Pause button answers right away: the bar switches to "stopping" and the step ends at its next safe point (in the classification, when the current window is done, which can take a few seconds with the local model). Nothing already done is lost.

To carry on, click Resume: the step continues from where it stopped. Closing the program or turning off the computer in the middle of a step has the same effect as a pause; when you open it again, just run the step or Run everything.

10. Machine sensors and the administrator prompt

This section is only for whoever wants to follow how hard the machine is working during a run; you can skip it without missing anything.

The Execution screen shows, in real time, the use of the processor, the memory and the graphics card, with temperature, power, frequency and fans. With the local model running, it also shows the card's memory in use and which model is loaded in it: that is how you see whether the model fit entirely.

The CPU sensors (temperature, power and the fan, which lives on the motherboard chip) can only be read with administrator rights. The Read CPU sensors and fans button asks for those rights whenever you want, for a small, separate reader; the program itself and your documents stay unprivileged. Answering No is safe: everything else keeps working, and the button stays available to try again. The installer also offers a shortcut that asks for this at startup, and a small optional component, PawnIO, which reads the temperature of the most recent processors.

What the words mean: a stopped fan is a real 0 RPM (modern graphics cards stop the fan when they are cool); needs administrator is a value that exists but needs the reader; not measured is a sensor the machine does not expose. On laptops, the fans usually belong to the manufacturer and only show up on some models (Dell, for example).

11. Result screen: what gets generated

All the files are saved in the output folder:

index.md
The table of contents: lists the groups and says which index file to open for each one; counts the legislation pages and points to normas-citadas.md.
index-<grupo>.md
One index per group: each item with its sheets, type, date, author, source file and page within it, plus a summary. The Confidence column appears only when some item is below high (high confidence) or low-confidence review is on. An index above 25 MB comes out in parts index-<grupo>-1.md, -2.md, split only between source files.
normas-citadas.md
One line per act recognized in the collection (law, decree, provisional measure, ordinance): type, number, date, summary, which groups and pages it appears in, and a link to the text on LexML. It only exists when there is at least one act. See Cited acts and searching the collection.
timeline.md
The chronology: the dated items, in order, without the Planalto acts. A group with more than 2,000 dated items gets its own timeline-<grupo>.md, and timeline.md points to it; that file stays outside the Claude package, because it repeats the group's index by date.
review.md
The check report: what was read, what failed, numbering gaps and removed documents.
project_instructions.md
The instructions for Claude: how to use the index, how to find an act and the rule of always confirming values in the original document.
buscar.bat
The topic search for Claude Code. See Cited acts and searching the collection.
  • Classification quality: a score based on the confidence the engine itself declared and on how many fields it filled in. It is not a measure of real accuracy; see What accuracy to expect.
  • Pending items: passages not yet classified, sheets with no item and files that failed. Resolve them before considering the collection ready.
  • Package for a new Claude Project: a .zip with the index files above (the buscar.bat stays only in the folder) and a step-by-step guide. Before the button, a table shows what goes in the package, with size and estimated tokens. A Claude Project has three limits: 30 MB per file; above about 500 thousand tokens, Claude starts consulting the material by search instead of reading all of it; above a few million, it stops answering well. The screen warns at the last two. A file above 30 MB never goes into the package, because the Project would refuse it; the screen lists what was left out. Usually, generating the reports again is enough for the index to come out in smaller parts; the exception is a single source file whose index alone exceeds 30 MB.
  • Free up space: deletes the converted copies and the blocks from the local work folder. Only do this once the reports are ready: the normal steps do not redo what was deleted, and an update of the collection that needs to read a document again puts it through OCR again, which takes time.

12. Cited acts and searching the collection

Cited acts

Pages of laws, decrees, provisional measures, ordinances and resolutions saved from the Planalto website are read from the structure of the page itself, without a model: type, number, date, author and summary come from the heading. Each act becomes a line in normas-citadas.md, with the groups and pages it appears in and a link to the text on LexML (the Senate's legislation portal). The text of the acts does not go into the Claude package: Claude opens the link when it needs it, and the instructions tell it so.

Search the collection

The index describes the items; the search finds any word of any file, including what lies beyond "Characters per page". Open Search the collection from the Execution or Result screens. Every word typed must appear; use "quotes" for an exact phrase and * at the end for the start of a word. Accents and capitals do not matter. Each result gives the file and the place inside it: the page, in a PDF, or the line, in a document read whole, such as a Word file or an e-mail. It highlights what was found, says when the passage was struck through in the original (in legislation, revoked) and has an Open file button. If the collection was read by an earlier version of the program, part of the files are not in the search yet: the screen says how many are missing, and the Add the missing files button adds them without rereading the rest.

LexML

The Also search LexML box queries the Senate's portal for the federal acts that deal with the term, even those not in your collection. Only the term you typed leaves the computer. Since 02/11/2026 the portal asks for a browser check before answering programs; when that happens, the screen says so and shows the link to run the search there. The program does not try to get around the check. The links to each act keep opening normally.

In Claude Code

The output folder has a buscar.bat: buscar.bat saneamento lists the files and pages where the term appears, with the act's link next to legislation passages; LexML is queried when no act in the collection cites the term or when you add --lexml. The folder's CLAUDE.md explains the command to Claude Code, and it uses it on its own when the question is about a topic.

13. Using it with Claude

On claude.ai (Projects)

  1. Create a new Project (or open the one for this collection).
  2. Paste the entire contents of project_instructions.md into the Project's instructions field.
  3. Upload as project knowledge everything in the package: index.md, the index-<grupo>.md files (and their parts, if any), normas-citadas.md, timeline.md and review.md. The timeline-<grupo>.md of a large group stays in the output folder, outside the package; the Result screen shows its size, and you decide whether to upload it separately.
  4. When you need the exact content of an item, send to the conversation only the original document the index points to. That is where the savings come from.

In Claude Code

Open Claude Code in the output folder (or in a folder that has access to it and to the source folder). Claude reads index.md, picks the group's index, uses buscar.bat when the question is about a topic and opens only the original files it needs, at the indicated page.

Why this saves: the index of a collection with thousands of pages is usually a tiny fraction of the size of the full text. Claude spends your quota reading the index and one or two items, not the whole collection.

14. Sets: several collections in one Project

Each project is one collection. When a question spans several ("what do we have on supplier X in contracts and in minutes?"), the Sets screen joins two or more projects into a single package, for a single Claude Project.

  • Creating a set: give it a name, check the projects and review each one's alias. The alias is proposed from the name ("Diretoria / Região Sul" becomes diretoria-regiao-sul) and goes at the start of every file name in the package: diretoria-regiao-sul__index.md and, for a project called "Contratos", contratos__index-Processo.md. That way no name collides, even when two projects have the same group. The Instructions you already use in the Project field goes to the top of the set's instructions.
  • The combined package: a single project_instructions.md with a section "Which collection to search" and one section per collection; the tables of contents and chronologies with their links already rewritten to the aliased names; the token budget added up, measured against the lowest limit among the projects.
  • Write to the folder: writes the same files to a folder of your choice, plus a CLAUDE.md that tells Claude Code where each collection is and how to search in each one. The folder cannot be a collection's source or output folder. Writing again keeps what you wrote outside the markers (see the next section) and deletes the files of an alias that no longer exists.
  • A project that is out of reach (folder from another computer, Drive off) or without reports appears disabled with the reason. If it was already part of the set, it stays in it and returns to the package when the folder is back.
  • Deleting a set only removes the entry from the list. It does not touch any project or any folder already written.

15. Your instructions are preserved

The text that GClaude Indexer writes in project_instructions.md and in the output folder's CLAUDE.md sits between two invisible markers (GCLAUDE-INDEXER:BEGIN and GCLAUDE-INDEXER:END).

  • Everything outside the markers is yours and is never deleted, not even during updates.
  • Each time the files are generated again, only the part between the markers is rewritten. What you pasted as instructions is not repeated.
  • If the output folder already had a CLAUDE.md of yours, it is kept and the program's block is added to it. A copy of the original is saved as CLAUDE.md.bak the first time.
  • If your Project already has instructions, paste them into the Instructions you already use field when creating the project: they go to the top of the file.
  • When the file has instructions of yours, the program's part becomes one section of them, Collection indexed by GClaude Indexer, with only the collection's numbers, files and rules. It has no title or role of its own, so it does not contradict what you wrote.
  • The same applies to the instructions and the CLAUDE.md of a set written to a folder.
  • At any time: the Project instructions link, on the Execution and Result screens, shows your part of the file so you can fix it or paste the current version from the Claude Project. The program's part is shown below it, read only. Each time you save, the previous version is kept in a .bak copy with the date in its name.
  • Repetition of the automatic block: if your part of the file already has a copy of what the program writes in the block (the non-negotiable rule, how to locate an item, the columns, counts of items or pages), generation does not touch your text: it puts a notice at the top of the block and in the log, and the Execution and Result screens show a link to review it. On the Project instructions screen you see the repeated sections, the lines with numbers only the block updates, and the "section 4" style references that would point to the block. Choose Remove the repetitions (the previous version is kept in a .bak copy) or Keep as it is. Passages of yours about the collection can go to the project's extra rules: tick the ones to move, and they appear inside the block.

16. Updating the collection

When the Execution screen opens, the program checks the source folder and its subfolders (it shows "Checking the source folder..."; on a large collection it takes a few seconds). If something changed, a notice shows how many documents are new, changed or removed. Click Update to see the plan before confirming.

  • New: they are read and classified.
  • Changed: they are read again (with OCR, if needed) and reclassified. A file whose OCR failed last time is also redone.
  • Removed: their pages and items leave the index, the converted copy is deleted and the name is recorded in review.md. If there was an identical copy of the document in the folder, that copy is indexed in its place.
  • Numbering change: in a case-file collection, sheet numbering is continuous within the group. If a document is added to or removed from the middle, the sheets of the documents after it change number. The plan shows which ones, and the log warns you. Old conversations that cited those sheets may become out of date.
  • Only the affected passages are reclassified; the rest is reused.
  • If the source folder cannot be read (disconnected disk, moved folder), the screen says so and offers nothing.
  • Project instructions: the update screen has a field with your instructions as they are in project_instructions.md. If you changed them directly in the Claude Project, paste the current version there: it replaces your part of the file, as pasted, and the previous version is kept in a .bak copy. If nothing changed, leave it as it is.
  • Stop: Update and Import and generate reports run in the background. A panel in the middle of the screen shows what is running, the elapsed time and a Stop button. Stopping writes nothing halfway: the update goes back to the state before the click, and in a report generation each file is either the old or the new one (the log says which changed). You can switch the theme, reload the page or open another tab: the panel stays. When it ends, the screen moves to the next step on its own.
  • Forgot to paste the instructions when updating? Use the Project instructions link afterwards; there is no need to update again.

After updating, use Run everything up to classification and Import and generate reports. Only the output files that changed are rewritten, and the log says which ones: those are the ones you upload to the Claude Project again.

17. Updating the program

Download the installer of the new version and install it over the old one, without uninstalling: the installer closes the old version if it is open, and your projects stay where they are. If the program is opened while the old version is still open, the new one replaces it and says so.

When the program is updated while it is open, a notice appears saying the system was updated: close the program and open it again from the shortcut. The About screen shows the installed version and the installation diagnostics.

After updating, generate the reports again in the projects you use: that is how they gain what the new version produces (for example, normas-citadas.md and buscar.bat) and lose what it no longer produces.

18. Another computer and team use

  • Output folder on Google Drive (or on a file server): the project can be opened from any computer that has access to it.
  • Shared catalog: on the Projects screen, point to a folder inside Drive to keep the list of projects. All computers with the same Drive will then see the same projects.
  • Usage lock: only one computer at a time works on a project. If another one is using it, the program tells you which. Closing the browser releases the lock in about five minutes; a machine that froze releases it in ten.
  • Golden rule when switching computers: close the program on the first one, wait for Google Drive to finish syncing, and only then open it on the second.
  • Sets are kept on each machine, not in the shared catalog.
  • Shared catalog or Open existing project? The catalog is the list of projects. Shared, it makes every computer with the same Drive see the same list, with nothing to do project by project. Open existing project adds to this machine's list one project it does not know: after reinstalling Windows, in a moved folder or in a folder someone sent you. Both use the project as it is; neither copies or redoes anything.

19. Themes and layouts

There are two independent choices, under Preferences (at the foot of the side bar) or at the top of the screen, depending on the layout:

  • Theme (the colors): Studio, Studio dark, Light, Dark, Sepia, High contrast, Aurora, Toga, Graphite and Ocean.
  • Layout (the shape: fonts, spacing, corners): Workspace, Default, Technical, Editorial and Compact.

The Workspace layout is the default since version 1.10.0. On the left there is a bar with the main screens and every project; the dot beside each project shows its status (green: imported; orange: in progress or with classification pending). The top shows where you are and, inside a project, tabs for Execution, Result, Search, Update collection and Instructions.

To go anywhere without the mouse, press Ctrl + K (or click "Search or run"): type part of the name of a screen, a project or a theme, choose with the arrows and press Enter. Accents do not matter. The palette only navigates and changes preferences; anything that starts work stays on the button of its own screen.

Whoever used another layout sees the Workspace once, after the update; to go back, just choose the old layout. The theme you chose before stays the same.

Any combination works. Your choice is saved in this browser. If Windows asks for less motion (an accessibility setting), animations are reduced on their own.

21. Common problems

"Project in use on another machine"
Close the program on the other computer. If it froze or was shut down, wait for the lock to expire or choose Take over anyway, only if you are sure the other one is not using it.
"Possible incomplete sync"
Google Drive has not finished downloading the project yet. Wait for the Drive icon to show that it is done.
"Database busy" or "operation in progress"
Another operation is using the project. Nothing was lost: wait for the activity bar to finish and try again.
The local engine fell back to "rules"
It only happens on a machine without a graphics card: Ollama is not running or there is not enough memory. It is not an error; the program goes back to the model when Ollama answers. With a graphics card, it waits for Ollama instead of falling back. The About screen shows the installation diagnostics.
Classification is slow and the graphics card almost empty
Check in the log whether the model fit in the card. If it did not, choose the smaller model under Local model.
Failed files in Pending items
These are usually password-protected, corrupted or text-free files. Open them, save an unprotected copy in the source folder and update the collection. A failed OCR is redone on its own in the next conversion.
Sheet gaps
Sheets with no classified item. Run the classification again on those passages or check whether the PDF has blank pages.
"Request refused" appears
Some website tried to send a command to the program and was blocked. Always use the GClaude Indexer shortcut or the address http://127.0.0.1:8000.
LexML asked for a check
The Senate's portal answers programs with a verification page. Open the link shown and run the search in the browser.

22. Privacy and security

  • Documents are read and classified only on this computer. The local engine talks only to the Ollama on this machine, never through the internet.
  • The program only accepts commands from its own screens: a website open in the browser cannot give it orders.
  • The source folder is never modified.
  • The project database stores the text of the pages. If the collection contains personal data covered by data-protection law (e.g. Brazil's LGPD, GDPR), protect the output folder as you would protect the documents themselves, including on Google Drive.
  • The only query to an outside service is the LexML search, which sends only the term you typed: on the screen, only with the box checked; in buscar.bat, also when no act in the collection cites the term.
  • When you use the Claude Code engine or send files to Claude, then yes, the content you send goes through your Claude account, under the terms of your plan.
