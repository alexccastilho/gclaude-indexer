1. What it is and what it is for

GClaude Indexer reads a folder full of documents (PDFs, Word files, spreadsheets, e-mails, scanned images…) and builds, on your computer, an organized index of everything in it: what each item is, its date, who it is from, and which page it is on. This index is made to be used with Claude.

It solves five problems:

  1. Saves your Claude subscription. Instead of sending the whole collection for Claude to read (which uses up a lot of your usage limit), you hand over just the index. Claude looks at the index, finds exactly which document and which page matter, and opens only that.
  2. Collections far larger than Claude can handle. Claude has a limit on how much text it can consider at once. A compact index, split by group, fits within that limit even when the collection has thousands of pages.
  3. Confidentiality. All the heavy work (reading, text recognition, classification) happens on this machine. No document is sent to the internet during processing. The database lives in a folder of yours — and if that folder is on Google Drive, you can use it from any computer.
  4. Incremental updates. When you add, change or remove documents, the system redoes only what changed, not the whole collection.
  5. Personal or business use. It works for a single person or for a team sharing the same folder on Drive or on a file server.

2. Quick start in 6 steps

  1. New project. Click + New project, give it a name, choose the Source folder (where your documents are) and check the suggested Output folder. Everything else can stay as it is. Click Create project.
  2. Run everything. On the Execution screen, click Run everything up to classification. You can leave the window open and do something else: the progress updates on its own.
  3. Generate the reports. When classification finishes, click Import and generate reports.
  4. Check. The Result screen shows the quality, the pending items and a preview of each generated file.
  5. Download the package. Under Package for a new Claude Project, click Download package (.zip).
  6. Take it to Claude. On claude.ai, create a Project, paste the contents of project_instructions.md into its instructions and upload the other files as project knowledge. See the details in Using it with Claude.

Tip: on every screen, the Help button at the top opens a summary of that screen, and the ? icon next to each field explains the field.

3. Projects screen

Lists every project this computer knows about. Each project lives entirely in its output folder (the project.db file inside it holds everything).

  • Status: not started (nothing read yet), in progress (some step is running), classification pending (there are still passages to classify) or the number of items already done.
  • Open: takes you to the project's Execution screen.
  • Delete: takes the project off the list. You choose between Only remove from the list (the files stay on disk) or also delete the generated files. In that case the system deletes only what it created itself (database, converted copies, reports). Your own files that are in the output folder are kept, and the folder only disappears if it ends up empty. The source folder is never touched.
  • Open existing project: for a project that is not on the list (reinstallation, new computer, folder received from someone else). Just point to the output folder.
  • Shared catalog: see Another computer and team use.

4. New project: every field

In most cases you only need to fill in Name and Source folder. The other fields already come with values that work well.

Identification

Project name
Just so you can recognize the project on the list. It does not change any file.
Collection theme
One or two sentences about the content (e.g. "bidding process for construction project X"). It goes into the instructions generated for Claude and helps the classification understand the context.

Folders

Source folder
Where the original documents are. It is never changed: the system only reads it.
Output folder
Where everything is saved. The default is the source folder with _indexado added at the end. It can be on Google Drive or on a file server so it can be used from other computers.

Collection

Collection type
case file numbers by sheet (f. 1, f. 2… — "f." stands for folio, a numbered sheet), like an administrative or court case file; the numbering carries on from one volume to the next. library numbers by page (p. 1, p. 2…), like books and reports.
How to group
A "group" is a set of files that form a unit (a case file with several volumes, for example). by subfolder uses the name of the first subfolder — the most common choice; by name pattern groups by the beginning of the file name, using the next field; all together treats the whole folder as a single group.
Grouping pattern
Only for by name pattern. It is a regular expression. Example: ^(\d{4}-\d+) puts "2024-001 - petição.pdf" and "2024-001 - despacho.pdf" into the group "2024-001".
Included extensions
Which file types are included. Check ALL to accept any text or document format (executables and compressed archives are never included). Web pages (.htm, .html, .mht…) are read as clean text, without the markup, and the encoding of every text file is worked out automatically (UTF-8, Windows-1252, ISO-8859-1…). Text struck through in the original — in HTML, DOCX, PPTX or XLSX — appears as ~~text~~: in legislation, that is a revoked or suppressed provision.

Slicing, windows and OCR

A window is a run of consecutive pages that the classifier reads at once to figure out where each item starts and ends.

Automatic proposal. When you choose the source folder, the program surveys a sample of it (up to 6 seconds) — how many PDFs, scanned or not, how many whole documents (HTML, DOCX, TXT…), page sizes and language — and proposes the five values below, each with its reason. Click Apply these settings to use them; nothing changes otherwise. The Analyse the folder and propose button runs it again after you change the extensions.

Pages per block (80)
PDFs larger than this are cut into parts before processing, so huge files do not get stuck.
Pages per window (16)
Smaller windows make fewer mistakes when many short documents are mixed together, but take longer. Larger windows are faster, but may merge two items into one.
Overlap (2)
How many pages from the end of one window are repeated at the start of the next, so an item is not cut in half. It must be smaller than Pages per window.
Characters per page (2000)
The limit of text from each page sent to the classifier. It keeps a page with a gigantic table from taking up the whole window.
OCR language
The language used to recognize the text of scanned pages: por (Portuguese), eng (English) or por+eng for both in the same collection.

Classification

Classification engine
What identifies the items. See the full comparison in Classification engines.
Local model
Which Ollama model the local engine uses. automatic uses the default (qwen3.5:4b). Choosing another one is useful for comparing quality.
Processing
Whether the local engine uses the graphics card (GPU). automatic and force GPU use as much of it as possible — much faster. CPU/RAM only leaves the card free for other programs, but is slower.
Parallelism
How many files conversion and reading process at the same time. economical: one at a time; automatic: uses the processor cores and leaves one free so you can keep using the computer (recommended); maximum: finishes sooner, but the computer gets slow in the meantime.
Review low confidence
First runs the rules engine (instant) on everything and sends to the chosen engine only the passages where the rules were unsure. Saves time when the collection has many standardized documents.

Project instructions

Instructions you already use
If your Claude Project already has instructions, paste them here. They stay at the top of the generated instructions file and are never deleted. See Your instructions are preserved.
Role in the instructions
Replaces the default paragraph that tells Claude what its role is in this collection (e.g. "you are a legal assistant…"). If left blank, the default text is used.
Extra rules
Rules specific to the collection, added at the end of the instructions (e.g. "always cite the case number", a glossary of acronyms).

6. Execution screen: the steps

Processing always follows this order. Each step can be interrupted and resumed: pausing, closing the program or even turning off the computer midway does not break anything — when you run it again, it picks up where it left off.

  • 1. Scan — finds the files in the source folder and identifies duplicate copies (a document identical to another is included only once).
  • 2–3. Conversion, OCR and slicing — turns each file into text. Scanned pages go through text recognition (OCR); huge PDFs are cut into blocks. This is the slowest step for scanned collections.
  • 4. Per-page extraction — stores the text of each page with its numbering (f. N or p. N).
  • 5. Window preparation — splits the pages into passages for classification.
  • 6. Classification — the chosen engine identifies each item: type, date, author, summary and page range.
  • Run next step: runs only the next step. Useful for following along step by step.
  • Run everything up to classification: chains all of them. This is what you will use almost every time.
  • Pause: stops what is running. To continue, run it again.
  • Import and generate reports: after classification, puts the items together and writes the files for Claude.
  • Live log: tells you what is happening, in plain language. The filter shows only warnings or only errors; copy copies the log so you can send it to someone.
  • Machine resources: processor, memory and graphics card usage in real time.
  • Claude Code engine: a box appears with the phrase to say to Claude Code (process the windows). Open Claude Code in the output folder, say the phrase and, when it finishes, click Recheck if the windows are done.

7. Result screen: what gets generated

All the files are saved in the output folder:

index.md
The table of contents: lists the groups and says which index file to open for each one.
index-<grupo>.md
One index per group: each item with its sheets, type, date, author, file and page within the PDF, plus a summary.
timeline.md
The chronology: the dated items, in order.
review.md
The check report: what was read, what failed, numbering gaps and removed documents.
project_instructions.md
The instructions for Claude: how to use the index and the rule of always confirming values in the original document.
  • Classification quality: a score based on the confidence the engine itself declared and on how many fields it filled in. It is not a measure of real accuracy — spot-check it.
  • Pending items: passages not yet classified, sheets with no item and files that failed. Resolve them before considering the collection ready.
  • Package for a new Claude Project: a .zip with all the files and a step-by-step guide.
  • Free up space: deletes the converted copies and the blocks (the converted/ and blocks/ folders). Only do this once the reports are ready: in a future update, documents that need to be read again will go through OCR again.

Search the collection

The index describes the items; the search finds any word of any file, including what lies beyond "Characters per page". Open Search the collection from the Run or Result screens. Every word typed must appear; use "quotes" for an exact phrase and * at the end for the start of a word. Accents and capitals do not matter. Each result gives the file, the page (PDF) or the article and line (whole document), highlights what was found, says when the passage was struck through in the original (in legislation, revoked) and has an Open file button. Projects extracted by an earlier version show an Add the missing files button.

8. Using it with Claude

On claude.ai (Projects)

  1. Create a new Project (or open the one for this collection).
  2. Paste the entire contents of project_instructions.md into the Project's instructions field.
  3. Upload as project knowledge: index.md, the index-<grupo>.md files, timeline.md and review.md.
  4. When you need the exact content of an item, send to the conversation only the original document the index points to — that is where the savings come from.

In Claude Code

Open Claude Code in the output folder (or in a folder that has access to it and to the source folder). Claude reads index.md, picks the group's index and opens only the original files it needs, at the indicated page.

Why this saves: the index of a collection with thousands of pages is usually a tiny fraction of the size of the full text. Claude spends your quota reading the index and one or two items, not the whole collection.

9. Your instructions are preserved

The text that GClaude Indexer writes in project_instructions.md and in the output folder's CLAUDE.md sits between two invisible markers (GCLAUDE-INDEXER:BEGIN and GCLAUDE-INDEXER:END).

  • Everything outside the markers is yours and is never deleted, not even during updates.
  • Each time the files are generated again, only the part between the markers is rewritten.
  • If the output folder already had a CLAUDE.md of yours, it is kept and the system's block is added to it. A copy of the original is saved as CLAUDE.md.bak the first time.
  • Instructions you already use in the Project can be pasted into the Instructions you already use field when creating the project: they go to the top of the file.

10. Updating the collection

When the source folder changes, the Execution screen shows a notice with how many documents are new, changed or removed. Click Update to see the plan before confirming.

  • New: they are read and classified.
  • Changed: they are read again (with OCR, if needed) and reclassified.
  • Removed: their pages and items leave the index, the converted copy is deleted and the name is recorded in review.md. If there was an identical copy of the document in the folder, that copy is indexed in its place.
  • Numbering change: in a case-file collection, sheet numbering is continuous within the group. If a document is added to or removed from the middle, the sheets of the documents after it change number. The plan shows which ones, and the log warns you. Old conversations that cited those sheets may become out of date.
  • Only the affected passages are reclassified; the rest is reused.

After updating, use Run everything up to classification and Import and generate reports, and upload the files to the Claude Project again.

11. Another computer and team use

  • Output folder on Google Drive (or on a file server): the project can be opened from any computer that has access to it.
  • Shared catalog: on the Projects screen, point to a folder inside Drive to keep the list of projects. All computers with the same Drive will then see the same projects.
  • Usage lock: only one computer at a time works on a project. If another one is using it, the system tells you which. The lock expires on its own after a period without use.
  • Golden rule when switching computers: close the program on the first one, wait for Google Drive to finish syncing, and only then open it on the second.

12. Themes and layouts

At the top of every screen there are two independent choices:

  • Theme (the colors): Light, Dark, Sepia, High contrast and the newer themes with more motion.
  • Layout (the shape: fonts, spacing, corners): Default, Technical, Editorial and Compact.

Any combination works. Your choice is saved in this browser. If the operating system asks for less motion (a Windows accessibility setting), animations are reduced automatically.

14. Common problems

"Project in use on another machine"
Close the program on the other computer. If it froze or was shut down, wait for the lock to expire or choose Take over anyway — only if you are sure the other one is not using it.
"Possible incomplete sync"
Google Drive has not finished downloading the project yet. Wait for the Drive icon to show that it is done.
The local engine fell back to "rules"
Ollama is not running or there is not enough memory. Open Ollama and run the classification again; the About screen shows the installation diagnostics.
Failed files in Pending items
These are usually password-protected or corrupted files. Open them, save an unprotected copy in the source folder and update the collection.
Sheet gaps
Sheets with no classified item. Run the classification again on those passages or check whether the PDF has blank pages.
"Request refused" appears
Some website tried to send a command to the program and was blocked. Always use the GClaude Indexer shortcut or the address http://127.0.0.1:8000.

15. Privacy and security

  • Documents are read and classified only on this computer. The local engine talks only to the Ollama on this machine, never through a proxy or the internet.
  • The program only accepts commands from its own screens: a website open in the browser cannot give it orders.
  • The source folder is never modified.
  • The project database stores the text of the pages. If the collection contains personal data covered by data-protection law (e.g. Brazil's LGPD, GDPR), protect the output folder as you would protect the documents themselves — including on Google Drive.
  • When you use the Claude Code engine or send files to Claude, then yes, the content you send goes through your Claude account, under the terms of your plan.
